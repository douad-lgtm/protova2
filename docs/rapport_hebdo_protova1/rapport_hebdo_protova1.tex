% ================= OBJECTIF =================
\section{Objectif de la semaine}

Rendre \textbf{ProtoVA1} (Jetson Nano, ROS~2 Foxy) de nouveau \textbf{pleinement
téléopérable} au volant Logitech G29 avec retour de force, en intégrant le nouvel
encodeur et son étage de filtrage --- première étape vers la démonstration finale :
\textbf{deux plateformes opérationnelles échangeant des messages V2V (DENM)}.

% ================= TRAVAUX =================
\section{Travaux réalisés}

\subsection{Micrologiciel Raspberry Pi Pico (réécrit, compilé, flashé)}
\begin{itemize}[itemsep=2pt]
  \item \textbf{FreeRTOS}, trois tâches : réception série
        (\texttt{CTRL,angle,vitesse}), contrôle servo + ESC, encodeur
        (\texttt{TICKS,n} à 50~Hz) ;
  \item \textbf{recalibration du neutre ESC : $1400 \rightarrow 1500~\mu$s} ---
        bug critique : à 1400~$\mu$s, la voiture partait en marche arrière rapide
        sur la commande \og stop \fg{} ;
  \item \textbf{armement automatique de l'ESC} : le signal neutre est désormais
        émis dès la mise sous tension (auparavant, le micrologiciel attendait
        l'ouverture du port série avant d'émettre le moindre signal, ce qui
        obligeait à débrancher puis rebrancher l'alimentation à chaque session).
\end{itemize}

\subsection{Encodeur KY-040 et conditionnement du signal}
\begin{itemize}[itemsep=2pt]
  \item chaîne validée : encodeur $\rightarrow$ filtre RC $\rightarrow$ bascule de
        Schmitt \textbf{74HC14} $\rightarrow$ Pico (élimination des rebonds
        mécaniques) ;
  \item étude des décodages possibles ($\times 1 = 20$, $\times 2 = 40$,
        $\times 4 = 80$ ticks/tour) $\rightarrow$ \textbf{décodage $\times 2$
        retenu : 40 ticks/tour} ;
  \item paramètres d'odométrie mis en cohérence côté ROS
        (\texttt{ticks\_per\_rev = 40} dans les n\oe uds TX et
        \texttt{ackermann\_odom}).
\end{itemize}

\subsection{Réseau : pont UDP pour le topic \texttt{/joy}}
\begin{itemize}[itemsep=2pt]
  \item diagnostic : le partage de connexion utilisé \textbf{bloque les données
        DDS} entre machines (la découverte passe, les données non) --- vérifié
        objectivement, l'UDP brut passant dans les deux sens ;
  \item développement d'un \textbf{pont UDP unicast} dédié : le PC envoie
        \texttt{/joy} sur le port 9001, la Jetson le republie localement
        $\rightarrow$ interopérabilité Humble (PC) $\leftrightarrow$ Foxy (Jetson)
        rétablie.
\end{itemize}

\subsection{Pile logicielle Jetson}
\begin{itemize}[itemsep=2pt]
  \item \texttt{twist\_mux} installé et configuré (priorités : AEB 255 $>$ PS4 60
        $>$ G29 30) --- prêt pour l'arrivée d'un freinage d'urgence coopératif ;
  \item script de lancement unique (\texttt{launch\_teleop\_p1.sh}) + service
        systemd \texttt{p1teleop} résilient aux coupures SSH ;
  \item \emph{runbook} complet documenté (flash $\rightarrow$ armement
        $\rightarrow$ lancement $\rightarrow$ conduite $\rightarrow$ diagnostic).
\end{itemize}
